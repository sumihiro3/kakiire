# Kakiire 設計書(Skitch代替 / Swift + AppKit)

Nov 2, 2026 · @Sumihiro

## 概要

Evernote Skitch の画像編集体験(リサイズ、枠・文字の追加、モザイク)を、Apple Silicon ネイティブの Mac 専用アプリとして独自実装する。

Skitch は Intel 版のみで Rosetta 前提のため、今後の macOS で使えなくなる。OSS の Sitch(phalladar/Sitch、MIT)は完成度が高いが、「書き出して終わり」が前提で、後から微調整できる編集用ファイル形式とレイヤー操作がない。

方針は次の3点。

- Swift + AppKit、Mac 専用(Windows 対応はしない)
- 編集用ファイル(元ファイル)を主役にし、PNG などは書き出し専用とする(PSD と PNG の関係)
- Sitch は設計資料と MIT コードの流用元として参照し、フォークはしない

アプリ名は Kakiire(書き入れ)。拡張子は `.kakiire`、UTType の識別子は `com.tep-lab.kakiire` とする。

## 要件

中心は「画像を開く→注釈→元ファイル保存→PNG 書き出し」で、キャプチャは後段とする。

### 機能要件

| 区分 | 内容 | フェーズ |
| --- | --- | --- |
| 入力 | 画像ファイルを開く、クリップボードから貼り付け、ドラッグ&ドロップ | 1 |
| 注釈 | 矢印(Skitch 風の先細り)、線、矩形、楕円、テキスト、モザイク、ぼかし | 1 |
| 注釈 | ハイライター、ペン、スタンプ(連番含む)、画像オーバーレイ | 3 |
| 編集 | 選択・移動・リサイズ、削除、Undo/Redo | 1 |
| 保存 | 編集用ファイルの保存・読み込み(全注釈を再編集可能) | 2 |
| 書き出し | PNG / JPEG、クリップボードへコピー、ドラッグで持ち出し | 1 |
| レイヤー | 一覧パネル、並べ替え、表示/非表示、ロック、名前 | 3 |
| 画像操作 | リサイズ(ピクセル指定・比率)、切り抜き、回転・反転 | 3 |
| キャプチャ | 範囲・ウィンドウ・全画面、グローバルホットキー、メニューバー常駐 | 4 |
| 仕上げ | Quick Look のサムネイル/プレビュー、ファイルアイコン | 5 |

### 非機能要件

- macOS 15 以降、Apple Silicon ネイティブ(Universal は任意)
- 外部依存なし(SwiftPM のみ)、完全オフライン、テレメトリなし
- 4K スクリーンショットでも注釈操作が 60fps 程度で滑らか
- 元ファイルは Google ドライブ等で共有しても壊れない単一ファイル

### スコープ外

- Windows / iOS 対応、クラウド共有・URL 発行
- 動画・GIF 録画、OCR、スクロールキャプチャ
- 複数人の同時編集

## アーキテクチャ

UI に依存しない Core ライブラリ(文書モデル・編集コマンド・レンダラー)を中心に、AppKit の App 層と入出力の I/O 層を分ける。Core は `swift test` だけで検証できる状態を保つ。

&#91;embedded content: モジュール構成 · 3層\]

App 層は Core に編集操作を渡すだけで、文書の中身を直接書き換えない。

### 文書モデル

- `Document` は値型(struct)で、`canvas`、`base`、`annotations: [Annotation]` を持つ
- `Annotation` は `id`、`name`、`hidden`、`locked` と、種類ごとの中身を持つ enum(`.arrow(ArrowSpec)` など)。Sitch のクラス継承と違い、そのまま Codable で JSON にできる
- 座標は元画像のピクセル座標。回転・反転は元画像と注釈の両方に適用し(無劣化で元に戻せる)、切り抜きとリサイズは `canvas` の値として非破壊に持つ

### 描画パイプライン

1. 元画像に回転・反転を適用する
2. モザイク・ぼかしを元画像(と画像オーバーレイ)に対して毎回計算する
3. 矢印・文字などの図形を重なり順に描く
4. 切り抜き範囲で切り出し、書き出し時は `outputScale` で縮小する

画面表示と書き出しは同じレンダラーを使う。モザイクは図形をぶらさないよう常に図形より下に描くため、レイヤーパネルでは効果系を図形の下にまとめて表示する。

### 保存と Undo

- NSDocument を使い、保存・自動保存・版の履歴・「最近使った項目」は OS に任せる
- Undo はまず「変更前の Document を丸ごと積む」スナップショット方式。値型なのでコピーは安く、元画像は参照を共有して重複しない
- ドラッグ中の連続した変更は1つの Undo にまとめる

## 編集用ファイル形式

元ファイルは単一の zip ファイル(拡張子 `.kakiire`)とし、元画像・注釈 JSON・素材・サムネイルを格納する。macOS のパッケージ(フォルダ形式)は Google ドライブ等でただのフォルダとして扱われ壊れやすいため使わない。

### 構成

```
example.kakiire(実体は zip)
├── manifest.json   形式バージョン、アプリバージョン、作成・更新日時
├── document.json   キャンバス、画像操作の状態、注釈リスト
├── base.png        元画像(取り込んだときのまま)
├── assets/         画像オーバーレイ用の画像(内容の SHA-256 をファイル名にして重複排除)
└── preview.png     焼き込み済みサムネイル(長辺 1024px まで)
```

PNG は既に圧縮済みなので無圧縮(stored)、JSON は deflate で格納する。zip を展開すれば、アプリがなくても元画像とプレビューは取り出せる。

zip の読み書きは自前の最小実装とし、外部ライブラリは使わない。

- 対応するのは無圧縮(stored)と deflate のみ。圧縮は Compression フレームワーク、CRC32 は zlib を使う
- 読み込みは末尾のセントラルディレクトリから行う。Finder で展開・再圧縮したファイルも開けるようにし、`__MACOSX` など知らないエントリは無視する
- ZIP64 には対応しない(1ファイル 4GB 未満で十分)

### document.json の骨子

```json
{
  "canvas": { "crop": [0, 0, 1920, 1080], "outputScale": 0.5 },
  "base": { "asset": "base.png", "rotation": 0, "flipH": false, "flipV": false },
  "annotations": [
    { "id": "8F1C…", "type": "arrow", "name": "矢印 1",
      "hidden": false, "locked": false,
      "geometry": { "from": [120, 80], "to": [400, 260] },
      "style": { "color": "#E5306B", "width": 8, "arrow": "tapered" } },
    { "id": "2A9D…", "type": "obscure", "name": "モザイク 1",
      "geometry": { "rect": [600, 40, 300, 60] },
      "style": { "mode": "pixelate", "strength": 12 } }
  ]
}
```

- 配列の順序がそのまま重なり順(先頭が最背面)
- 注釈は UUID を持ち、レイヤーパネルや将来の差分比較で識別に使う
- 座標はすべて元画像のピクセル座標。切り抜きとリサイズは `canvas` の値として持ち、元画像は書き換えない(非破壊)

### バージョニング

- `manifest.formatVersion` は整数。互換性を壊す変更のときだけ上げる
- フィールド追加は互換扱い。古いアプリは知らないフィールドを無視する
- 知らない `type` の注釈は JSON のまま保持し、再保存しても消さない(表示はプレースホルダ)
- 新しすぎる形式は読み取り専用で開き、その旨を表示する

### モザイクと元画像

元ファイルの `base.png` はモザイク前の画像なので、元ファイルは PSD と同じく「伏せる前の情報を含むもの」として扱う。社外に出すのは書き出した PNG / JPEG のみとし、書き出しでは必ずモザイク・ぼかしを焼き込む。

将来の選択肢として、伏せた部分だけを `base.png` に焼き込んでから保存する「共有用に保存」を検討する(他の注釈は編集可能なまま)。

## Sitch からの流用方針とライセンス

[Sitch](https://github.com/phalladar/Sitch) は MIT なので、コードの流用は著作権表示と LICENSE を残せば自由。設計の考え方と資料の価値が特に高い。

| 対象 | 扱い | 備考 |
| --- | --- | --- |
| `docs/SPEC.md`、`docs/research/digest.md` | 設計資料として参照 | Skitch 本家の操作仕様、ShareX / Greenshot / Flameshot の設計比較 |
| 範囲キャプチャのオーバーレイ、ホットキー | 流用しない | フェーズ4で `screencapture -i` を使い続けることにした(ADR 0003) |
| モザイク・ぼかしの描画 | コード流用候補 | 下の内容から毎回再計算する非破壊方式 |
| 先細り矢印の描画 | コード流用候補 | Skitch らしさの要 |
| 注釈モデル(クラス継承) | 流用しない | Codable な値型で作り直す |
| エディタ UI、ツールバー | 参考のみ | レイヤーパネル前提で作り直す |

- 流用したファイルは冒頭に出典を書き、`THIRD_PARTY_NOTICES.md` に Sitch の MIT 表記を載せる
- ShareX・Greenshot・Flameshot は GPL のため、調査メモの考え方は参考にしてもコードは写さない

Sitch から引き継ぐ設計原則は次のとおり。

- 元画像は不変、注釈(モザイク含む)は順序付きのオブジェクトリスト
- モザイク・ぼかしは描画ごとに再計算し、焼き込みは書き出し時のみ
- 書き出しでは効果系を先、図形を後に描き、矢印などがぼけないようにする
