# Kakiire フェーズ4の方針:キャプチャ、署名、作図ツールでつかむ範囲、テキストのリサイズ

## 決定

| 項目 | 決定 |
|---|---|
| 撮影の仕組み | OS 標準の `screencapture -i` を使い続ける。ScreenCaptureKit で範囲選択の画面は自作しない(handoff にあった Sitch のオーバーレイの流用はやめる) |
| 撮影中の隠し方 | `NSApp.hide` は使わず、見えているウインドウを `orderOut` する。撮り終えたら戻し、撮る前のキーウインドウをキーに戻す |
| 署名 | Debug・Release とも「Apple Development」(チーム EBBVRDHK5Z)。Developer ID と公証はフェーズ5で入れる |
| グローバルショートカット | Carbon の `RegisterEventHotKey`。既定は ⌃⇧⌘5 で、撮った画像は新しいウインドウで開く。設定で「使わない / ⌃⇧⌘5 / ⌃⌥⌘S / ⌥⇧⌘2」から選ぶ。キーを自由に記録する UI は作らない |
| メニューバー | `NSStatusItem` を置き、撮影・クリップボードから新規・開く・設定・終了を出す。設定で消せる。Dock のアイコンは残す。ウインドウを全部閉じても終了しない |
| 作図ツールのまま注釈をつかむ | 同じ種類の注釈だけ(矢印ツールなら矢印)。手前に別の種類があっても、その下にある同じ種類を探す。それ以外の場所では今どおり新しく描く(矩形の中に矩形を描ける) |
| テキストツールで既存のテキストを押したとき | ドラッグすれば移動、動かさずに離せば編集 |
| テキストのリサイズ | 四隅のつまみ。反対の隅を固定し、新しい外形に収まるよう文字サイズを変える(幅と高さの比の小さいほう、4〜400)。折り返しはしない。文字サイズは段に合わせない |
| 文字の大きさのショートカット | ⌥⌘+ / ⌥⌘- はテキストを選んでいなくても効かせ、次に打つ文字の大きさを変える |
| 画像の挿入 | 「画像 › 画像を挿入」(ファイルから⇧⌘I / スクリーンショットから)と、編集画面へのドロップは、どれも今の文書に画像オーバーレイとして重ねる。新しい文書として開くのは、起動画面と Dock へのドロップ・⌘O・⌃⇧⌘N |

## 理由

- `screencapture` は範囲選択・ウインドウ選択・マルチモニタ・Retina 混在を OS がそのまま扱う。自作すると工数が大きく、マルチモニタの検証も要る。撮った直後にそのまま注釈できる、といった自作の利点は今は要らない
- `NSApp.hide` で隠すと別のアプリが前面になる。macOS 14 以降は前面化が協調式で、撮影後の `NSApp.activate()` は前面のアプリが譲らない限り通らず、Kakiire が前に戻らなかった。ウインドウを外すだけなら Kakiire は前面のまま
- 画面収録の許可(TCC)は、署名の指定要件(designated requirement)で照合される。ad-hoc 署名だと指定要件が cdhash になり、ビルドのたびに許可が外れる。Apple Development 署名なら証明書名で決まるので、ビルドし直しても残る(実機で確認)。ad-hoc の頃の登録は照合できないので、`tccutil reset ScreenCapture com.tep-lab.kakiire` で消して入れ直す
- `RegisterEventHotKey` は OS に登録したキーだけが届く仕組みで、キー入力を監視しない。Sandbox の中でもアクセシビリティの許可なしに使える
- 作図ツールでどの注釈でもつかめるようにすると、注釈の上に重ねて描けなくなる。同じ種類だけなら、描き直しと位置の調整の両方がツールを持ち替えずにできる
- ⌥⌘- が「効かない」と見えたのは、テキスト以外が選ばれている(何も選んでいない選択ツールを含む)ときにメニューが無効になっていたため
