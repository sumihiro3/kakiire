# メイカーコイン

Kakiire のメイカーコイン(3D プリンタで刷って配るコイン)。表は 5 案出して B(矢印)と E(モザイク)に絞った。裏は共通で LP の QR。
AMS で刷る前提。寸法はどれも仮で、実物はまだ刷っていない。

| ファイル | 中身 |
|---|---|
| `sheet.png` / `sheet.svg` | 表と裏を並べたシート |
| `front-arrow.svg`・`front-mosaic.svg` | 表の図案(B 矢印・E モザイク) |
| `back.svg` | 裏の図案(共通) |
| `print/kakiire-coin-arrow.3mf`・`kakiire-coin-mosaic.3mf` | 刷るための立体。色ごとの部品を 1 つのオブジェクトにまとめてある |
| `print/kakiire-coin-*-<色>.stl` | 同じ立体を色ごとに分けた STL(原点は共通)。3MF がうまく読めないときに使う |
| `print/preview.png` | 書き出した立体を上から見た絵(左が表、右が裏) |
| `back-compare.png` | 裏に枠と字を入れるかを決めたときの比較(くぼみ式だった頃の控え。作り直さない) |

## 作り直すとき

```bash
python3 scripts/coin/make-coin.py          # 図案(SVG・シート)と検査用のマスク
python3 scripts/coin/make-coin.py --all    # 見送った A アイコン・C 番号スタンプ・D 書き入れ も出す
build/coin/venv/bin/python scripts/coin/make-model.py   # 立体(3MF・STL)。先に make-coin.py を動かしておく
```

立体を作る環境は 1 回だけ用意する:

```bash
uv venv build/coin/venv --python 3.13
uv pip install --python build/coin/venv/bin/python -r scripts/coin/requirements.txt
```

図形・寸法・文言は `scripts/coin/make-coin.py` だけが持つ。`make-model.py` は SVG を読んで積むだけで、図形を持たない。
`make-coin.py` は Chrome(画像化)と Xcode の `swiftc`(QR と字の輪郭)を使う。

## 仮の寸法

- 直径 40 mm、縁の幅 1.6 mm。厚みは B が 2.8 mm、E が 3.2 mm
- 高さはどれも 0.2 mm の倍数(層の厚み 0.2 mm で刷る想定)
- 0.4 mm ノズルの目安として、線は 0.8 mm 以上、すき間は 0.6 mm 以上。`make-coin.py` が段ごとに測り、細い所に印を付けた画像を `build/coin/thin-*.png` に出す(0.5 mm² までの小さな欠けは、とがった角として数えない)

## 色と層の並び

フィラメントは白・黒・赤(B)、白・黒・グレー(E)。2 枚合わせて 4 色なので、AMS 1 台で同じプレートに並べられる。
どれも Bambu Lab の PLA。赤だけ PLA Matte、ほかは PLA Basic と見ている。図と 3MF の色はその色コード(Jade White `#FFFFFF`・Black `#000000`・Gray `#8E9089`、Matte の Scarlet Red `#DE4343`)に合わせてある。

| 高さ(mm) | B 矢印 | E モザイク |
|---|---|---|
| 0〜0.4(1・2 層目) | 白 + 黒(QR と枠) | 白 + 黒(QR と枠) |
| 0.4〜2.4 | 白 | 白 |
| 2.4〜2.8 | 赤(矢印・字・縁) | グレー(タイル・字・縁) |
| 2.8〜3.2 | — | 黒(高いタイル・字・縁) |

表の色は高さの段で分けてあり、同じ層に 2 色が来るのは裏の 1・2 層目だけ。縁はいちばん上の段の色になる。

## 刷るとき

- 3MF を Bambu Studio で開き、部品(white / black / red / gray)にフィラメントを割り当てる。**Studio で開けるかはまだ確かめていない**(この Mac に Studio がない)。部品つきの 1 つのオブジェクトとして開かなければ、色別の STL をまとめて読み込み、「複数の部品を持つ 1 つのオブジェクト」にする
- 3MF にはスライサーの設定を入れていない(不完全な設定を入れると Studio が開けなくなった前例がある)。プリンタと層の厚み 0.2 mm は Studio で選ぶ
- 向きはそのまま(裏が下、z = 0)。サポートは要らない

## SVG の読み方(`make-model.py` が従う規則)

- 単位は mm、原点はコインの中心、y は下向き
- グループ 1 つが 1 段。`data-tier` が段の番号(0 は地、1 から上が表の段、-1 は裏に埋め込む黒)、`data-z-top` がその段の上面の高さ
- `data-cut="true"` のグループは、その形で下の段を地の面まで削る(今の 2 案では使っていない)
- 段 n の立体は「段 n 以上のグループを全部合わせた形から、cut の形を引いたもの」。上の段の下には下の段の色が入るので、E の黒いタイルや字の側面には、下の段のグレーが帯で見える(シートの絵は真上から見た色だけ)
- `back.svg` は裏から見た向き。立体では 180° 回して置く(左右を裏返さない)
- 字は輪郭にしてある(フォントが要らない)。英字は SF Rounded。小さい英字は A・R の穴をふさいである
- **字形は仮**。SF Rounded を配り物に使えるかは未確認(Apple 向けアプリの画面の試作に用途が限られている可能性がある)。LP と同じ IBM Plex(OFL)などへ差し替えるかを決める。差し替えたら `make-coin.py` → `make-model.py` の順に作り直す

## 裏

- QR の中身は `HTTPS://KAKIIRE.TEP-LAB.COM`。大文字だけだと英数字モードになり、25×25 マスで済む(小文字のままだと 29×29)。誤り訂正は Q
- 1 マス 0.84 mm(0.42 mm の線 2 本ぶん)。黒いマスと枠は、白と同じ高さに埋め込む(下から 0.4 mm)
- 黒い枠は幅 1.6 mm で縁いっぱいまで(表の縁と同じ幅)。QR の角から枠まで 4.2 マスで、規格の余白 4 マスを満たす
- 字「KAKIIRE」は入れない(表にある。枠と両方入れると QR のまわりの余白が足りなくなる)
- 平らな面にして、造形のときはこの面をベッド側にする

## 検査

`make-coin.py` は、図を画像にして QR を読み、URL が一致するか確かめる(ぼかして縮めた版、コインの外を暗くした版でも)。

`make-model.py` は、書き出した 3MF と STL を読み直して次を確かめ、合わなければ失敗で終わる:

- 部品ごとに閉じた立体か、部品どうしが重なっていないか、直径 40 mm・厚み・底が z = 0 か
- 表: 段ごとの断面が、図案のマスク(`build/coin/mask-*.png`)から 0.05 mm を超えてずれていないか、その高さにほかの色が入っていないか
- 裏: 立体を左右に裏返して上から見た形が、`back.svg` のマスクと合うか(鏡像ならここで落ちる)。その絵から QR を読めるか

実物のコインで QR を読めるか、スマホのカメラで大文字の URL が開くかは、まだ確かめていない。

## 見送った案

- A アイコン: 5 色になる
- C 番号スタンプ: 番号は 1 枚ごとに変えられる(`design_stamp` の数字)
- D 書き入れ: 「書」の横画が約 0.6 mm で、目安の 0.8 mm を切る(横画が 8 本あり、直径 40 mm では太らせられない)
